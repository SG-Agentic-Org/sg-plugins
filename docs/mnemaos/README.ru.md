# MnemaOS

**Дайте вашему ИИ память, которая принадлежит вам.**

MnemaOS — устанавливаемый набор навыков. Он расспрашивает, как вы работаете с LLM, и собирает вам
систему памяти: локальную папку с обычными Markdown-файлами. ИИ читает её в начале каждой сессии и
дописывает, когда работа закончена. Без SaaS, без базы данных, без аккаунта. Память — это просто
файлы: их можно читать, править, бэкапить и забрать с собой.

→ Полные описания: [`about.ru.md`](about.ru.md) (RU) · [`about.md`](about.md) (EN)
→ Сам навык: [`skills/mnemaos/`](../../skills/mnemaos/) (его и устанавливать)

## Для кого

Для всех, кто работает с LLM (ChatGPT, Claude, кодинг-агент, локальная модель) и устал каждую
сессию заново объяснять контекст. Технических знаний не нужно. Работает и в веб-чате, и с
кодинг-агентом на вашей машине.

## Какую боль решает

ИИ забывает всё между чатами. Вы заново вставляете, кто вы, какие проекты, какой тон, что уже
пробовали. Заметки, если они есть, разрозненны, и ИИ сам их не читает. MnemaOS превращает это в
структурированную память, которую агент читает сам и держит в порядке.

## Чем отличается

| | Что вы получаете |
|---|---|
| **от обычного Obsidian-хранилища** | Obsidian хранит заметки. MnemaOS добавляет протоколы — startup, closure, distillation, hygiene — чтобы заметки читал и поддерживал сам ИИ, а не только вы. |
| **от промта «запомни это»** | Промт — один абзац, который модель может потерять. MnemaOS — устойчивая структурированная папка с версиями и контрактом. |
| **от RAG / векторной базы** | Без эмбеддингов, сервера и инфраструктуры. Поиск — «открыть индекс, открыть файл». Текст, который можно грепнуть. |
| **от SaaS-памяти** | Без вендора. Локальный Markdown под вашим контролем. Удалите пакет — память остаётся. |

## Два способа начать

- **С нуля (greenfield)** — начинаете с пустой папки; онбординг собирает чистое хранилище вокруг вас.
- **Поверх существующей папки (adopt)** — уже есть хаотичная рабочая папка на сотни файлов? MnemaOS
  делает аудит **только на чтение**, предлагает структуру, **ждёт вашего согласования**, **делает
  полный бэкап** и раскладывает файлы в чистый слой памяти с migration report. **Ничего не двигается
  до согласования, оригинал всегда сначала забэкаплен.**

## Что будет с вашими файлами

В режиме adopt: ничего не трогается до согласования плана. Затем делается полная копия с меткой
времени (`_mnemaos_backup/original-…/`) **до** первого переноса. Файлы **копируются** в новую
структуру, а не удаляются при переносе. Мусор и дубли он **помечает**, а не удаляет сам — решаете вы.
Откатиться из бэкапа можно всегда.

## Установка

1. Скопируйте папку [`skills/mnemaos/`](../../skills/mnemaos/) в директорию навыков вашего агента.
2. Попросите агента «настрой мне память через MnemaOS» (или вызовите навык `mnemaos`).
3. Ответьте на интервью из шести измерений. Агент сгенерирует хранилище и четыре навыка памяти.
4. Он прогонит smoke-тест и крошечный живой прогон, чтобы вы увидели, что память работает.

Запуск рутин под конкретный хост агент пропишет в сгенерированный `SETUP.md` во время онбординга.

## Опционально: собственный сервер памяти (MCP)

Файловая система выше — законченная сама по себе. Если нужен больший охват, в пакете есть
[`skills/mnemaos-mcp/`](../../skills/mnemaos-mcp/README.md) — маленький сервер памяти (Python на стандартной
библиотеке, ноль зависимостей), который отдаёт тот же vault **любому LLM-клиенту с поддержкой
MCP** через шесть инструментов: `memory_context`, `memory_search`, `memory_get`, `memory_list`,
`memory_write`, `memory_health`. Три конфигурации, выбираются одним дополнительным вопросом
онбординга:

1. **Только файлы** — без сервера; агент читает и пишет vault напрямую.
2. **Локально** — одна команда, и vault доступен каждому MCP-приложению на вашем компьютере,
   с быстрым ранжированным полнотекстовым поиском.
3. **Удалённо** — тот же сервер на вашем VPS за ~$5 за HTTPS и токеном: память получают веб- и
   мобильные клиенты. Пошаговая инструкция с конфигами systemd/Caddy/Docker —
   [`skills/mnemaos-mcp/deploy/vps-setup.md`](../../skills/mnemaos-mcp/deploy/vps-setup.md).

Карточки с пометкой `private: true` никогда не отдаются удалённо — удалённый транспорт не может
их вернуть в принципе. Индекс, который строит сервер, — производные данные: удаляйте в любой
момент, пересобирайте одной командой; vault остаётся простым Markdown, который принадлежит вам.

## Чего не делает (границы)

- Не публикует, не пишет от вашего имени, не платит и не удаляет важные данные без вашего явного
  согласия.
- Не запускает в облаке то, что вы не видите.
- Сама память никогда не зависит от сервера: MnemaOS — локальная система памяти на Markdown и
  полностью работает как таковая. MCP-сервер — опциональная надстройка; векторной базы,
  эмбеддингов, мобильного приложения и SaaS в пакете по-прежнему нет.

## Privacy / local-first

Обычный Markdown на вашей машине. Без SaaS, без аккаунта, без телеметрии. Пакет не хранит ключей —
они ему не нужны. Встроенный smoke-тест ловит любой вписанный секрет и любое протёкшее имя из чужой
конфигурации.

## Три коротких примера

- **Вика — email-маркетолог, только веб-ChatGPT.** Без CLI, без локальных файлов. MnemaOS собирает
  ей чистое хранилище с нуля и отдаёт startup/closure как блоки для копирования — и не обещает
  автоматизацию, которую веб-режим не потянет. Если позже она разместит опциональный сервер
  памяти, веб-клиент с поддержкой пользовательских MCP-коннекторов подключит её память напрямую.
- **Катя — руководитель контента и SEO, большая хаотичная папка, ставит Codex.** MnemaOS принимает
  её папку: аудит на чтение → карта папки → предложенная структура → её согласование → полный бэкап →
  копирование файлов в новый слой → migration report → индекс и smoke-тест.
- **Продвинутый пользователь — уже есть Obsidian-хранилище.** MnemaOS накладывается поверх, не ломая:
  добавляет протоколы, индекс и «мост»-карточки, которые ссылаются на существующие заметки, и не
  перестраивает хранилище. Существующие файлы остаются неизменными байт в байт.
